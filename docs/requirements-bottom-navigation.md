# 需求文档：底部导航与四大模块（App 形态）

**版本**：v0.2  
**状态**：已补充 Tab3 命名与周期记账规则（待开发排期）  
**关联项目**：accounting-app（React + Vite + CloudBase）

---

## 1. 背景与目标

### 1.1 背景

当前 Web 记账以单页纵向堆叠为主；主要使用设备为手机。希望改为 **类原生 App 的底部导航（Tab Bar）**，降低功能查找成本，突出「快速记账」。

### 1.2 目标

- **核心路径最短**：打开 App → 默认落在「记账」→ 完成一笔记录 ≤ 3 步（在理想网络下）。
- **结构清晰**：四大模块职责边界明确，避免同一数据在多处维护规则不一致。
- **可迭代**：第一期可只实现导航壳 + 部分模块，其余占位或简化版。

### 1.3 非目标（本期可不承诺）

- 应用商店原生壳（若仍为浏览器 PWA，则「类 App」指交互形态）。
- 完整离线编辑与冲突合并（若有，另立专项）。

## 2. 用户与典型场景

| 角色     | 场景简述 |
|----------|----------|
| 普通用户 | 随时记一笔；当天花了多少一眼可见。 |
| 复盘用户 | 按日/月/年回看支出结构；按类别筛选。 |
| 规划用户 | 设月度预算、看日均与进度；配置房贷/车贷等周期扣款。 |
| 账号用户 | 登录/退出、邮箱、同步状态说明。 |

## 3. 信息架构（底部导航）

共 **4 个 Tab**，从左到右固定顺序（图标与文案可微调，顺序不建议频繁变动）：

| 序号 | Tab 名称 | 定位 | 备注 |
|------|----------|------|------|
| 1 | **记账** | 核心：新增流水 + 今日概览 | 默认首页 |
| 2 | **账单** | 全部流水：检索、时间维度、类别 | 原「明细」升维 |
| 3 | **更多功能** | 预算管理、周期记账等增强能力 | 对外统一使用该名称 |
| 4 | **我的** | 账号、设置、关于 | — |

**设计原则**

- **记账**页不放复杂筛选；「看历史/筛类」去 **账单**。
- **预算 / 周期记账** 集中在 **更多功能**，避免「我的」过重。
- **我的** 仅保留账号与偏好，不放业务记账表单。

## 4. 功能需求分模块

### 4.1 Tab 1：记账（核心）

#### 4.1.1 记一笔

- **功能**：新增收入/支出（字段与现有一致：类型、金额、分类、日期、备注）。
- **默认**：进入页面默认「支出」、日期为今天、焦点策略可配置（如优先金额）。
- **提交后**：清空表单或保留类型（产品定一种）；列表区立即反映（乐观更新可选）。

#### 4.1.2 今日账单

- **功能**：展示 **自然日 = 今天** 的流水列表（按时间倒序）。
- **范围**：与「记账」同属 Tab1，**仅今日**，不替代全量账单页。
- **操作**：支持点击进入编辑/删除（权限与现有一致）。
- **空状态**：无今日记录时的引导文案。

**验收要点**

- [ ] 底部 Tab「记账」为默认路由。
- [ ] 今日列表与「日期为今天」的流水数据一致。
- [ ] 新增一笔今日支出后，今日列表无需切换 Tab 即可更新。

---

### 4.2 Tab 2：账单（明细 / 全览）

#### 4.2.1 全量账单列表

- **功能**：展示当前登录用户 **全部** 流水（分页或虚拟滚动，数据量大时必选一种）。
- **排序**：默认按交易日期降序，同日按创建时间降序（与现网逻辑对齐）。

#### 4.2.2 时间维度查看

| 维度 | 说明 | 交互建议 |
|------|------|----------|
| **日** | 选择某日，展示该日流水 | 日期选择器 + 列表 |
| **月** | 选择某月，展示该月流水或月汇总入口 | 与现有 `YYYY-MM` 一致 |
| **年** | 选择某年，展示该年流水或年汇总 | `YYYY` |

- **一致性**：类别、类型等筛选 **作用于当前所选日 / 月 / 年范围内的结果**。

#### 4.2.3 按类别筛选

- **功能**：类别多选或单选 +「全部」；与所选时间维度 **组合查询**。
- **可选**：类型筛选（全部 / 收入 / 支出）与现有一致。

#### 4.2.4 其他

- **导出**：CSV 导出范围 = 当前筛选结果（与现有一致或显式写清）。
- **编辑/删除**：与现有一致。

**验收要点**

- [ ] 日/月/年三种维度可切换，列表与汇总与后端数据一致。
- [ ] 类别筛选与时间维度组合正确。
- [ ] 与 Tab1「仅今日」边界清晰：Tab1 不重复承担全量检索。

---

### 4.3 Tab 3：更多功能（预算 + 周期记账）

#### 4.3.1 预算管理

- **功能**：月度总预算；按当月天数折算日均参考；今日支出占日均、本月累计占预算（与现有实现/产品说明一致）。
- **数据**：独立 `budgets` 集合（或等价存储）；与流水聚合分离。

#### 4.3.2 周期记账

**定义**：用户配置一条 **周期性支出模板**（如房贷、车贷、分期）。系统在 **每个账期实际记账日** 将一笔支出 **自动写入** `transactions`，无需用户当日再点确认。

**配置项（建议最小集）**

| 字段 | 说明 |
|------|------|
| 名称 | 如「房贷」「车贷」 |
| 金额 | 固定金额（首期可不做浮动） |
| 分类 | 映射到现有支出分类 |
| 周期 | 每月（首期可仅支持「每月」） |
| 记账日号 | 用户选择每月几号（1–31），语义见下节「账期日对齐」 |
| 持续月数 | 正整数；到期后规则自动结束 |
| 开始月份 | 从哪个月开始参与生成 |
| 状态 | 启用 / 暂停 / 已结束 |

##### 账期日对齐（已明确）

用户设定的「记账日号」在部分月份不存在（如 **31 日、30 日** 在 2 月或短月）。

- **规则**：每个自然月计算 **该月内的实际记账日** = **用户设定日号** 与 **该月最大自然日** 取较小值，即：

  `实际日 = min(记账日号, 该月最后一天)`  

  等价描述：**若该月没有用户指定的号数，则自动落到当月最后一个自然日**（在当月内「向下」对齐到最近可用日，与常见扣款日习惯一致）。

- **示例**：记账日号 31 → 1 月为 31 日，4 月为 30 日，2 月为 28 日（闰年 29 日）；记账日号 30 → 2 月为 28/29 日。

##### 生成策略（已明确）

- **到日自动生成**：到达 **该月实际记账日**（按上节对齐后的日历日期）时，系统自动创建一条 **支出** 流水。
- **幂等**：同一周期任务、同一 **实际记账日** 仅允许生成 **一条** 流水（避免重复打开 App、重试网络导致重复记账）。
- **可追溯**：生成的流水需带标记（如 `source: recurring`、`recurring_id`），列表与详情可区分；用户仍可 **编辑 / 删除** 单条流水（删除策略与是否回写模板状态可二期细化）。

##### 触发方式（实现层建议，写入需求便于排期）

- **推荐**：腾讯云 **定时触发云函数**（按日扫描应生成任务）或等价后端调度，保证用户不打开 App 也会记账。
- **兜底**：用户打开 App 时 **补跑** 当日应生成但未生成的任务（与幂等结合）。

**验收要点**

- [ ] 29/30/31 在各月的实际记账日与上表一致。
- [ ] 到实际记账日自动出现对应支出，且同任务同日不重复。
- [ ] 流水可识别来源为周期记账；持续月数到期后不再生成。

### 4.4 Tab 4：我的

- **账号**：当前邮箱展示、退出登录。
- **可选**：同步说明、数据安全简短说明、意见反馈入口。
- **设置（可选迭代）**：货币单位、主题、默认分类等。

**验收要点**

- [ ] 登录态与退出与现网一致；不重复承载 Tab3 业务功能。

## 5. 全局与交互

### 5.1 底部 Tab Bar

- **常驻**：主流程四页底部固定（键盘弹出时可隐藏或压缩，需单独 UI 说明）。
- **状态**：当前 Tab 高亮；支持浏览器返回键与路由同步（若 PWA / SPA）。

### 5.2 路由结构（建议）

```
/ledger          → Tab1 记账
/transactions    → Tab2 账单
/more            → Tab3 更多功能（子路由示例：/more/budget、/more/recurring）
/me              → Tab4 我的
```

（路径名可按工程习惯调整，**产品对外名称**统一为「更多功能」。）

### 5.3 与现有代码关系

- 现有单页能力拆分到上述路由；共享 CloudBase 与类型定义。
- **预算** 入口迁至 **更多功能** Tab。

## 6. 非功能需求（摘要）

| 类别 | 要求 |
|------|------|
| 性能 | 账单列表大数据量时分页或虚拟列表；首屏可骨架屏。 |
| 安全 | 读写仅本人数据；`.env` 不入库。 |
| 兼容 | 移动端安全区、触控区域 ≥ 44px（沿用现有方向）。 |
| 可访问 | 关键按钮有可读标签；进度条保留语义（如有）。 |
| 周期记账 | 生成接口需幂等；日志便于对账。 |
